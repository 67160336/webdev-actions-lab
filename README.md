1) GitHub Actions แตกต่างจาก GitHub Pages อย่างไร?
GitHub Actions คือระบบทำงานอัตโนมัติ เมื่อมีเหตุการณ์เกิดขึ้น เช่น การ push ก็จะรันชุดคำสั่งที่เขียนไว้ใน Workflow (ดึงโค้ด ตรวจสอบ อัปโหลด deploy) ส่วน GitHub Pages คือบริการโฮสต์เว็บไซต์ static ที่นำไฟล์ HTML, CSS, JavaScript ไปเผยแพร่ให้เข้าถึงผ่าน URL สาธารณะ สรุปคือ Actions เป็นตัว "ลงมือทำงาน" และ Pages เป็นที่ "แสดงเว็บไซต์" ในแล็บนี้ Actions ทำหน้าที่ส่งเว็บไซต์ไปให้ Pages 
2) เหตุใดจึงเลือก trigger ด้วย push ที่ branch main?
branch main คือสาขาหลักที่เก็บโค้ดเวอร์ชันที่พร้อมใช้งานจริง เมื่อ trigger ที่ push ไป main ทุกครั้งที่แก้ไขและ push เว็บไซต์จะถูก deploy ใหม่เองโดยไม่ต้องทำด้วยมือ ซึ่งเป็นหลักของ Continuous Deployment และยังป้องกันไม่ให้โค้ดที่ยังทำไม่เสร็จใน branch อื่นถูกเผยแพร่โดยไม่ตั้งใจ 


3) ถ้าแก้ไฟล์ในเครื่องแต่ไม่ได้ push เว็บไซต์จะเปลี่ยนหรือไม่ เพราะเหตุใด?
ไม่เปลี่ยน เพราะการแก้ไฟล์ในเครื่องอยู่แค่ในคอมพิวเตอร์ของเรา GitHub ยังไม่เห็นการเปลี่ยนแปลง และ Workflow ถูกสั่งให้เริ่มด้วยเหตุการณ์ push เท่านั้น เมื่อไม่มีการ push ก็ไม่มี Workflow รัน GitHub Pages จึงยังแสดงเวอร์ชันเก่าอยู่ ต้อง commit และ push ขึ้นไปก่อน 
4) เหตุใดโปรเจกต์ PHP + MySQL จึงไม่สามารถนำไปรันบน GitHub Pages ได้โดยตรง?
GitHub Pages รองรับเฉพาะเว็บแบบ static คือส่งไฟล์ HTML, CSS, JavaScript ให้เบราว์เซอร์ไปทำงานต่อ ไม่มีเซิร์ฟเวอร์ที่ประมวลผลภาษา PHP และไม่มีฐานข้อมูล MySQL ให้ใช้ PHP ต้องรันฝั่งเซิร์ฟเวอร์เพื่อสร้างหน้าเว็บและเชื่อมต่อฐานข้อมูล ถ้านำไปวางบน Pages ไฟล์ PHP จะถูกส่งเป็นข้อความธรรมดาหรือโหลดไม่ได้ ต้องใช้ Hosting ที่รองรับ PHP และ MySQL หรือแยกเฉพาะส่วนหน้าเว็บมาใช้กับ Pages 
5) อธิบายขั้นตอนการค้นหาสาเหตุ เมื่อ Workflow มีสถานะ Failed
Actions → คลิก run ที่ล้มเหลว → ดู step ที่เป็นสีแดง → อ่าน log หาข้อความ error → แก้ไฟล์ → push ใหม่ เอาไปเรียบเรียงใหม่ด้วยภาษาของคุณเองได้
